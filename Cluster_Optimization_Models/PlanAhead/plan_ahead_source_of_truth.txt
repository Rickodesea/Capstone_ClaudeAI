================================================================================
INTRODUCTION
================================================================================

The plan-ahead model is a Mixed-Integer Second-Order Cone Program (MISOCP)
solved periodically (once per planning horizon, e.g., daily or at the start of
each simulation run) to answer:

  "Which nodes should each tenant be prioritised on for each planning period,
   given their estimated aggregate resource demand?"

It does NOT schedule individual jobs.  It operates on tenant-level usage
profiles u_{i,h} — the forecasted total resource consumption of tenant i
during planning period h.  This is the key architectural difference from the
original workload-level formulation.

The output is a TenantAccessSchedule: a soft priority hint, not a hard block.
The real-time scheduler boosts its objective coefficients for (tenant, node)
pairs in the schedule; it may still place jobs elsewhere if needed.

Pipeline:
  [Prediction Model]   ---> u_{i,h}  (aggregate tenant usage forecast per period)
  [Operator Config]    ---> C_n, pi_n, pi_bar_i, sigma_frac, kappa, lam_s
  [Plan-Ahead MISOCP]  ---> solved once per planning horizon
                       ---> outputs TenantAccessSchedule y_{i,n,h}
  [Real-Time Model]    ---> called every epoch; receives priority hints
                       ---> boosts objective coefficient b=2.0 for prioritised
                            (tenant, node) pairs; b=1.0 elsewhere

Model class: Mixed-Integer Second-Order Cone Program (MISOCP).
  The cone constraint C1b ensures the probabilistic capacity guarantee with
  complexity that meets the academic expectations of the formulation.

Simulation-speed option: a plain MILP mode (use_socp=False) drops C1b and the
  slack variable t_{n,h}.  This is used only during interactive simulation
  (plan-ahead fires every 50 steps).  It is NOT the primary formulation.


================================================================================
§1  DECISION VARIABLES
================================================================================

  f_{i,n,h}  >= 0        Continuous allocation of node n's capacity to tenant i
                          in period h.  Interpreted as the fraction of C_n
                          reserved for tenant i.

  y_{i,n,h}  in {0,1}    Priority indicator.  y=1 means the plan-ahead recommends
                          tenant i be prioritised on node n in period h.
                          This is the primary output variable — it forms TAS.

  z_{n,h}    in {0,1}    Node-active indicator.  z=1 if node n is in use in
                          period h (driven up by C5 whenever any y_{i,n,h}=1).

  t_{n,h}    >= 0         Cantelli slack.  The solver sets this to the smallest
                          value satisfying C1b.  It represents the safety margin
                          (in capacity units) that C1a reserves on node n in
                          period h.  Present only in MISOCP mode (use_socp=True).

  a_i        in {0,1}    Admission indicator.  a_i=1 iff tenant i is admitted
                          for the planning horizon.

  sigma      in [0,1]    Fairness auxiliary.  The solver maximises this as the
                          minimum demand-satisfaction ratio across admitted tenants.


================================================================================
§2  SETS
================================================================================

  T        Tenants: T = {0, 1, ..., |T|-1}
  N        Cluster nodes: N = {0, 1, ..., |N|-1}
  H        Planning periods: H = {0, 1, ..., |H|-1}
           Each period represents a coarse time block (e.g., a 4-hour window).
           |H| = floor(plan_ahead_interval / access_period)  in simulation.


================================================================================
§3  PARAMETERS
================================================================================

────────────────────────────────────────
§3.1  Demand and Uncertainty
────────────────────────────────────────

  u_{i,h}      Estimated total resource demand of tenant i in period h.
               This is the AGGREGATE expected usage across all of tenant i's
               workloads during period h — not per-job demand.
               Source: prediction layer (e.g., ARIMA or LSTM time-series model
               trained on historical instance_usage from Google cluster traces,
               aggregated to planning-period granularity per tenant).
               Unit: capacity units (same scale as C_n).

               Key property: aggregate tenant demand is significantly more
               forecastable than individual job arrival patterns.  Literature
               on datacenter workload forecasting (Google traces v3) shows
               aggregate demand is predictable at 15-min to 4-hour windows
               using standard time-series methods.

  sigma^2_{i,h}  Per-tenant demand variance in period h.
               Computed as:  sigma^2_{i,h} = (sigma_frac * u_{i,h})^2
               This models uncertainty proportional to predicted usage:
               a larger forecast implies larger absolute uncertainty.
               Used in the SOCP cone constraint C1b.

  sigma_frac   Fractional uncertainty parameter (operator-configured scalar).
               Represents std dev of actual demand as a fraction of u_{i,h}.
               Typical range: 0.05–0.20 depending on forecast quality.
               Higher sigma_frac -> larger safety buffer -> more conservative.

  kappa(eps)   Cantelli one-sided safety factor:  kappa = sqrt((1 - eps) / eps)
               eps = tail probability (probability of capacity overrun allowed).
               eps=0.10 -> kappa=3.00 (90% coverage guarantee)
               eps=0.05 -> kappa=4.36 (95% coverage guarantee)
               Default: eps=0.10, kappa=3.00.

────────────────────────────────────────
§3.2  Infrastructure
────────────────────────────────────────

  C_n          Capacity of node n (capacity units).
               Source: MachineEvents.capacity from Google cluster traces,
               or operator configuration.

  pi_n         Infrastructure cost per active node-slot.
               Coefficient on z_{n,h} in the objective.

────────────────────────────────────────
§3.3  Pricing
────────────────────────────────────────

  pi_bar_i     Contract revenue from admitting tenant i.
               (e.g., billing rate per planning horizon)

  v_op_i       Operational cost of serving tenant i (support, overhead).
               Net revenue per admitted tenant = pi_bar_i - v_op_i.

────────────────────────────────────────
§3.4  Objective Weights
────────────────────────────────────────

  lam_0        Weight on infrastructure cost (always active).
  lam_1        Weight on admission revenue (negative in objective = maximise).
  lam_2        Weight on fairness sigma (negative in objective = maximise).

  Typical defaults:
    lam_0 = 1.0  (infra cost)
    lam_1 = 2.0  (admission revenue — heavier than cost)
    lam_2 = 0.5  (fairness — minor regulariser)


================================================================================
§4  PROBABILISTIC CAPACITY CONSTRAINT (SOCP / Cantelli)
================================================================================

The plan-ahead model must guarantee with high probability (1 - eps) that
actual resource usage on each node does not exceed capacity, despite the
stochastic nature of tenant demand.

Uncertainty model:
  Actual demand of tenant i on node n in period h is modelled as:
    D_{i,n,h} ~ mean f_{i,n,h},  variance sigma^2_{i,h} * y_{i,n,h}

  The y_{i,n,h} term scales variance by the priority assignment: only tenants
  prioritised on a node contribute variance to that node's total uncertainty.

Cantelli inequality (one-sided Chebyshev):
  For a random variable X with mean mu and variance v^2:
    P[ X <= mu + kappa * v ] >= 1 - eps
    where kappa = sqrt((1-eps)/eps)

Applied to the sum of demand across all tenants on node n in period h:
  P[ sum_i D_{i,n,h} <= sum_i f_{i,n,h} + kappa * sqrt(sum_i sigma^2_{i,h}*y_{i,n,h}) ]
    >= 1 - eps

This leads to two linked constraints (C1a and C1b):

C1a (linear capacity):
  sum_i f_{i,n,h}  +  kappa * t_{n,h}  <=  C_n * z_{n,h}    for all n, h

C1b (second-order cone):
  sum_i sigma^2_{i,h} * y_{i,n,h}  <=  t_{n,h}^2            for all n, h

  Equivalently: t_{n,h} >= || sqrt(sigma^2_{i,h}) * y_{i,n,h} ||_2

  This is a rotated second-order cone constraint.  In Gurobi it is
  implemented as:
    model.addQConstr(
        t[n,h] * t[n,h] >= quicksum(sigma2[i,h] * y[i,n,h] for i in T)
    )

Together C1a + C1b enforce:
  P[ actual total usage on node n in period h <= C_n * z_{n,h} ] >= 1 - eps

This is the SOCP component that makes the model a MISOCP.

Comparison to original formulation:
  Original C2 (per-workload Cholesky):
    mean_load_{n,r,t} + kap_n * || chol_r * xi_vec_{n,r,t} ||_2 <= C_{n,r} * z_{n,t}
    where chol_r = Cholesky(Sigma_r), Sigma_r = covariance matrix of all workloads.

  Refactored C1a+C1b (per-tenant usage variance):
    sum_i f_{i,n,h} + kappa * t_{n,h} <= C_n * z_{n,h}
    t_{n,h}^2 >= sum_i sigma^2_{i,h} * y_{i,n,h}

  Both are SOCP constraints; both enforce P[usage <= capacity] >= 1-eps.
  The difference is the uncertainty source:
    - Original: requires full workload covariance Sigma_r (unknowable at planning time)
    - Refactored: requires only sigma_frac * u_{i,h} (estimable from usage traces)


================================================================================
§5  CONSTRAINTS
================================================================================

C1a — Linear capacity with safety buffer:

  sum_{i in T} f[i,n,h]  +  kappa * t[n,h]  <=  C[n] * z[n,h]
    for all n in N, h in H

  Reserves safety headroom kappa*t_{n,h} on each active node-period.
  In MILP mode (use_socp=False): t_{n,h} is absent; constraint is
    sum_{i} f[i,n,h] <= C[n] * z[n,h]

C1b — Cone (SOCP): safety buffer must cover combined uncertainty:

  sum_{i in T} sigma^2_{i,h} * y[i,n,h]  <=  t[n,h]^2
    for all n in N, h in H  (present only when use_socp=True)

  The solver sizes t_{n,h} to be at least sqrt(sum_i sigma^2_{i,h} * y_{i,n,h}).
  Combined with C1a, this ensures the probabilistic capacity guarantee (§4).
  Absent in MILP mode.

C2 — Priority link (allocation implies priority):

  f[i,n,h]  <=  C[n] * y[i,n,h]      for all i in T, n in N, h in H

  If y[i,n,h]=0 then f[i,n,h]=0 (no allocation without a priority assignment).
  The big-M coefficient C[n] is the tightest valid bound.

C3 — Demand satisfaction (admitted tenants must be served):

  sum_{n in N} f[i,n,h]  >=  u[i,h] * a[i]    for all i in T, h in H

  An admitted tenant (a_i=1) must receive total allocation at least equal to
  their estimated demand in every period.  Rejected tenants (a_i=0) have RHS=0
  (constraint is trivially satisfied).

C4 — Fairness (min demand-satisfaction ratio over admitted tenants):

  sigma  <=  (sum_{n,h} f[i,n,h]) / (sum_h u[i,h])  +  (1 - a[i])
    for all i in T  (where sum_h u[i,h] > 0)

  The (1 - a[i]) term deactivates the constraint for rejected tenants (they
  do not drag sigma down).  The objective maximises sigma, so the solver
  maximises the minimum satisfaction ratio across all admitted tenants.

C5 — Node activation (a node must be active if any tenant is prioritised there):

  z[n,h]  >=  y[i,n,h]      for all i in T, n in N, h in H

  Ensures z_{n,h}=1 whenever the solver assigns a priority y_{i,n,h}=1,
  correctly accounting for the infrastructure cost of activating node n.


================================================================================
§6  OPTIMIZATION OBJECTIVE
================================================================================

  min   lam_0 * INFRA_COST
      - lam_1 * ADMISSION_REVENUE
      - lam_2 * FAIRNESS

Where:

  INFRA_COST        =  sum_{n in N, h in H} pi_n * z[n,h]
                       Total infrastructure cost of active node-periods.

  ADMISSION_REVENUE =  sum_{i in T} (pi_bar_i - v_op_i) * a[i]
                       Net revenue from admitted tenants.

  FAIRNESS          =  sigma
                       Min demand-satisfaction ratio across admitted tenants.
                       Maximised (via negative sign in minimisation objective).

Typical weight defaults:
  lam_0 = 1.0  (infra cost)
  lam_1 = 2.0  (admission revenue — heavier to incentivise admitting tenants)
  lam_2 = 0.5  (fairness — ensures equitable allocation without dominating)


================================================================================
§7  COMPLETE MODEL SUMMARY
================================================================================

Decision variables:
  f[i,n,h]   continuous >= 0        (|T| * |N| * |H| variables)
  y[i,n,h]   binary                 (|T| * |N| * |H| variables)
  z[n,h]     binary                 (|N| * |H| variables)
  t[n,h]     continuous >= 0        (|N| * |H| variables — SOCP mode only)
  a[i]       binary                 (|T| variables)
  sigma      continuous in [0,1]    (1 variable)

Total binary variables: O(TNH + NH + T)
Total continuous variables: O(TNH + NH + 1)  [+NH for t in SOCP mode]

Objective:
  min  lam_0 * sum_{n,h} pi_n * z[n,h]
     - lam_1 * sum_i (pi_bar_i - v_op_i) * a[i]
     - lam_2 * sigma

Constraints:
  C1a   Linear capacity with safety buffer (or plain capacity in MILP mode)
  C1b   Second-order cone on safety slack t_{n,h}  (SOCP mode only)
  C2    Priority link: f <= C[n] * y
  C3    Demand satisfaction: sum_n f >= u * a
  C4    Fairness: sigma <= total_alloc / total_demand + (1-a)
  C5    Node activation: z >= y

Solver: Gurobi
  Model type: MISOCP (Mixed-Integer Second-Order Cone Program) when use_socp=True
              MILP  (Mixed-Integer Linear Program)              when use_socp=False
  TimeLimit = 300 s,  MIPGap = 1%
  Default (standalone): use_socp=True (MISOCP)
  Simulation mode:      use_socp=False (MILP, for speed)

Output: TenantAccessSchedule
  dict[ (tenant_id: int, period: int) -> node_ids: list[int] ]
  Derived from y[i,n,h].X > 0.5 post-solve.
  Passed to the real-time model, which uses it as a priority boost (b=2.0)
  rather than as a hard access constraint.


================================================================================
§8  MODEL OUTPUT AND INTERFACE TO REAL-TIME MODEL
================================================================================

The plan-ahead model's primary output is the TenantAccessSchedule:

  TAS[(i, h)] = { n in N : y[i,n,h].X > 0.5 }
    for each tenant i in T, for each period h in H

This is a PRIORITY HINT, not a hard constraint.  The real-time model uses it
to set objective boost coefficients:

  b_{t(j), n} = 2.0  if n in TAS[(t(j), current_period)]
  b_{t(j), n} = 1.0  otherwise

Jobs are never blocked from non-priority nodes.  The boost guides placements
toward the plan-ahead recommendation while preserving feasibility under any
real-time capacity state.

At real-time scheduling epoch for period h:
  active_hints = { (i, n) : n in TAS[(i, h)] for i in T }
  solve(jobs, nodes, W_t, priority_boosts=active_hints)

Output data structure example:
  { (0, 0): [2, 3, 4],
    (0, 1): [2, 3],
    (1, 0): [0, 1],
    (1, 1): [0, 1, 4] }


================================================================================
§9  CONNECTION TO GOOGLE CLUSTER-USAGE TRACES v3
================================================================================

Parameters derivable from Google traces:

  u_{i,h}         Aggregate usage     -> InstanceUsage.average_usage (CPU, MEM)
                                         aggregated per tenant per planning window.
                                         Sum over all instances of tenant i in window h.

  C_n             Node capacity       -> MachineEvents.capacity (CPU, MEM)

  sigma_frac      Fractional uncert.  -> estimated from coefficient of variation of
                                         per-tenant usage within historical windows
                                         (std dev / mean of tenant's hourly usage).

Parameters that must be synthesised (not directly in traces):
  pi_n, pi_bar_i, v_op_i   Pricing — operator-defined
  lam_0, lam_1, lam_2      Objective weights — operator priority
  kappa (= eps)             Risk tolerance — operator SLA policy
