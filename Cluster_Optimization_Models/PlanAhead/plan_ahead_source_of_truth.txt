================================================================================
INTRODUCTION
================================================================================

The plan-ahead model is a Mixed-Integer Second-Order Cone Program (MISOCP)
solved once per planning horizon (every horizon_steps simulation intervals).

It answers: "Which machines should each tenant be assigned to for each planning
period, given their estimated demand, machine pool, and feedback from the
previous horizon?"

IMPORTANT: MISOCP (use_socp=True) is the DEFAULT mode in ALL contexts:
  - Simulation (every horizon_steps intervals)
  - Pipeline (all samples: Simple, Medium, High)
  - Sensitivity analysis
  - All tests
  MILP mode (use_socp=False) is available as an opt-in option only and is
  NEVER enabled by default anywhere.

Three-layer pipeline:
  [Plan-Ahead MISOCP]  ---> runs once per horizon_steps intervals (e.g., 50)
                       ---> outputs: tenant groups + machine assignments per period
  [Cluster Manager]    ---> per-interval loop; reads plan output for current period
                       ---> filters jobs and machines per tenant group
  [Real-Time MILP]     ---> called once per group per interval
                       ---> places individual jobs; returns placement dict

Feedback loop (after each horizon):
  - Realtime reports violation rates v_bar_n (per machine, k-window rolling average)
  - Realtime reports wait times W_bar_i (per tenant, k-window rolling average)
  - Plan-ahead inflates demand for high-wait tenants and shrinks capacity of
    overloaded machines on the next plan-ahead call


================================================================================
§1  SETS
================================================================================

  T = T_e ∪ T_s     All tenants

  T_e                Exclusive tenants.
                     - Receive dedicated machines for the ENTIRE horizon.
                     - Machines assigned to exclusive tenants are off-limits to
                       all shared tenants (C_sep constraint).
                     - Assignment is fixed: same machines for all periods h in H.

  T_s = T \ T_e      Shared tenants.
                     - May share machines with other shared tenants.
                     - Assignment can change per period h.
                     - Partitioned into heavy (T_h) and light (T_l) for mix bonus.
                     T_h = { i in T_s : avg_h u_{i,h} >= median over T_s }
                     T_l = T_s \ T_h

  M = M_a ∪ M_b     All machines in the cluster pool.

  M_a                Always-available machines (|M_a| = n_always_available).
                     Always active (z_{n,h} = 1 forced). No activation cost.

  M_b                Additional machines (M \ M_a).
                     Model decides which to activate (z_on_n = 1).
                     Activation cost pi_n applies.

  H = {0, 1, ..., |H|-1}   Planning periods.
                     Each period spans period_steps simulation intervals.
                     |H| = max(1, horizon_steps // period_steps)


================================================================================
§2  PARAMETERS
================================================================================

Machine parameters:
  C_n          Resource capacity of machine n (in GB or capacity units)
  C_eff_n      Effective capacity after feedback:
               C_eff_n = C_n * (1 - alpha * v_bar_n)
               High violation rate -> smaller effective capacity -> fewer tenants
  pi_n         Activation cost for additional machine n in M_b

Tenant demand parameters:
  u_{i,h}      Expected demand of shared tenant i in period h (raw, before feedback)
  u_fb_{i,h}   Feedback-adjusted demand (used in C3 and Cantelli):
               u_fb_{i,h} = u_{i,h} * (1 + beta * min(2, W_bar_i / W_bar_ref))
               The min(2,...) cap prevents infeasibility at very high wait times.
  u_max_i      Peak demand of exclusive tenant i: max_{h in H} u_{i,h}
  sigma^2_{i,h} Demand variance: (sigma_frac * u_{i,h})^2
               Note: variance uses the PRE-FEEDBACK demand u_{i,h}, not u_fb.
               This means the Cantelli buffer is sized to raw uncertainty only.

Uncertainty parameters:
  sigma_frac   std dev of actual demand as fraction of u_{i,h} (default 0.20)
  eps          Cantelli tail probability (default 0.10 -> 90% coverage)
  kappa        Cantelli safety factor: sqrt((1-eps)/eps)
               eps=0.10 -> kappa=3.00
               eps=0.05 -> kappa=4.36

Feedback parameters:
  v_bar_n      Rolling SLA violation rate per machine (fraction, [0,1])
               Computed over last k_window intervals from realtime layer.
  W_bar_i      Average scheduling wait time per tenant (in intervals)
               Computed over last k_window intervals from realtime layer.
  alpha        Capacity shrinkage coefficient (default 0.5)
               C_eff_n = C_n * (1 - 0.5 * v_bar_n) means a 100% violation rate
               halves the effective capacity.
  beta         Demand inflation coefficient (default 0.3)
               At W_bar_i = W_bar_ref: scale = 1 + 0.3*1 = 1.30 (30% more demand)
  W_bar_ref    Reference wait time in intervals (default 10)
               At W_bar_i = W_bar_ref the scale factor is exactly 1+beta = 1.30.
               At W_bar_i = 2*W_bar_ref the scale hits the cap: 1+beta*2 = 1.60.

Policy parameters:
  m_min        Minimum machines per shared tenant per period (default 2).
               Ensures resilience: tenants can absorb one machine spike/failure.
               Calibrated with SOCP demand thresholds: with epsilon=0.10 and
               sigma_frac=0.20, kappa=3.0, a single node can absorb demand up to
               C_n / (1 + kappa*sigma_frac) = C_n / 1.6. Setting usage > C_n/1.6
               forces the model to assign m_min >= 2 naturally via SOCP physics.

Objective weights:
  lam_0        Infrastructure cost weight (default: infra cost zeroed in sim = 0.0)
  lam_1        Fairness weight (positive -> maximises sigma, default 5.0 in tests)
  lam_2        Mix bonus weight (default 2.0 in tests)


================================================================================
§3  DECISION VARIABLES
================================================================================

  e_{i,n}      in {0,1}    1 iff exclusive tenant i in T_e is assigned machine n.
                            Fixed for the entire planning horizon (all periods share
                            the same exclusive assignment).

  z_on_{n}     in {0,1}    1 iff additional machine n in M_b is activated.
                            Activation cost pi_n applies when z_on_n = 1.

  z_{n,h}      in {0,1}    1 iff machine n is active in period h.
                            For M_a: forced to 1 by C_aa.
                            For M_b: z_{n,h} <= z_on_n (by C_act).

  y_{i,n,h}    in {0,1}    1 iff shared tenant i in T_s is assigned machine n in
                            period h. This is the primary output: it defines which
                            machines the Cluster Manager uses for each tenant group.

  f_{i,n,h}    >= 0        Capacity allocated from machine n to shared tenant i in
                            period h. Used to model demand satisfaction and SOCP.

  sigma        in [0,1]    Minimum demand-satisfaction ratio across all shared
                            tenants (fairness measure, maximised in objective).

  t_{n,h}      >= 0        Cantelli slack (SOCP mode only). Upper bound on the
                            weighted demand std dev on machine n in period h.
                            solver sizes this as: t_{n,h} >= sqrt(sum_i sigma2*y)

  hH_{n,h}     in {0,1}    1 iff machine n has >= 1 heavy-demand tenant in period h.
  hL_{n,h}     in {0,1}    1 iff machine n has >= 1 light-demand tenant in period h.
  mix_{n,h}    in {0,1}    1 iff machine n has BOTH heavy and light tenants in h.
                            Rewarded by lam_2 in objective (co-location bonus).


================================================================================
§4  CONSTRAINTS
================================================================================

Machine Activation
──────────────────

C_aa (Always Available):
  z_{n,h} = 1    for all n in M_a, h in H
  Always-on machines are always active.

C_act (Additional Machine Activation):
  z_{n,h} <= z_on_n    for all n in M_b, h in H
  Additional machines active only if switched on.

C_zact (Machine Active if Assigned):
  z_{n,h} >= y_{i,n,h}    for all i in T_s, n in M, h in H
  A machine must be active whenever any shared tenant is assigned to it.

Exclusive Tenant Constraints
────────────────────────────

C_excl1 (At Most One Exclusive Per Machine):
  sum_{i in T_e} e_{i,n} <= 1    for all n in M
  Each machine can be held exclusively by at most one exclusive tenant.

C_excl2 (Each Exclusive Must Be Assigned):
  sum_{n in M} e_{i,n} >= 1    for all i in T_e
  Every exclusive tenant must receive at least one machine.

C_excl_cap (Exclusive Capacity Coverage):
  sum_{n in M} e_{i,n} * C_n >= u_max_i    for all i in T_e
  Machines assigned exclusively to tenant i must cover its peak demand.

C_sep (Exclusive-Shared Separation):
  sum_{i in T_e} e_{i,n} + y_{j,n,h} <= 1
    for all j in T_s, n in M, h in H
  A machine assigned exclusively to any exclusive tenant cannot be used
  by any shared tenant in any period.

Shared Tenant Constraints
──────────────────────────

C_share (Minimum Machine Assignment):
  sum_{n in M} y_{i,n,h} >= m_min    for all i in T_s, h in H
  Every shared tenant receives at least m_min machines per period.
  Default m_min = 2 (configurable via min_machines_per_tenant).
  Provides resilience and distributes demand across multiple nodes.

C1a (Capacity with Cantelli Safety Buffer):
  sum_{i in T_s} f_{i,n,h} + kappa * t_{n,h} <= C_eff_n * z_{n,h}
    for all n in M, h in H
  Total allocation plus the Cantelli safety buffer fits within effective capacity.
  In MILP mode: same without the kappa*t term (t absent).

C1b (Cantelli Cone — SOCP only):
  sum_{i in T_s} sigma^2_{i,h} * y_{i,n,h} <= t_{n,h}^2
    for all n in M, h in H
  Second-order cone: t_{n,h} >= sqrt(sum_i sigma2_{i,h} * y_{i,n,h}).
  Together C1a + C1b guarantee:
    P[ total demand on machine n in period h <= C_eff_n ] >= 1 - eps

C2 (Priority Link):
  f_{i,n,h} <= C_n * y_{i,n,h}    for all i in T_s, n in M, h in H
  Allocation can only occur where the tenant is assigned (y=1).

C3 (Demand Satisfaction):
  sum_{n in M} f_{i,n,h} >= u_fb_{i,h}    for all i in T_s, h in H
  Every shared tenant receives at least its feedback-adjusted demand.

C4 (Fairness — Min Demand-Satisfaction Ratio):
  sigma <= (sum_{n,h} f_{i,n,h}) / (sum_h u_fb_{i,h})
    for all i in T_s where sum_h u_fb_{i,h} > 0
  sigma is the minimum fraction of total demand satisfied across all shared
  tenants. Maximised in objective.

Mix Bonus Constraints (linearised AND gate):
  hH_{n,h} >= y_{i,n,h}            for all i in T_h, n in M, h in H
  hL_{n,h} >= y_{j,n,h}            for all j in T_l, n in M, h in H
  mix_{n,h} <= hH_{n,h}            for all n, h
  mix_{n,h} <= hL_{n,h}            for all n, h
  mix_{n,h} >= hH_{n,h} + hL_{n,h} - 1    for all n, h
  mix_{n,h} = 1 iff machine n has >=1 heavy AND >=1 light tenant in period h.


================================================================================
§5  PROBABILISTIC CAPACITY CONSTRAINT (SOCP)
================================================================================

Why Cantelli?
  We know only the mean u_{i,h} and variance sigma^2_{i,h} of tenant demand —
  not the full distribution. Cantelli's inequality is distribution-free: it
  provides a one-sided safety bound using only mean and variance.

Model:
  Actual demand of shared tenant i on machine n in period h is a random variable
  with mean f_{i,n,h} and variance sigma^2_{i,h} * y_{i,n,h}.
  (Variance is zero when the tenant is not assigned to the machine.)

Cantelli bound:
  P[ D_{n,h} > mu_{n,h} + kappa * sigma_tot_{n,h} ] <= eps
  where: mu_{n,h} = sum_i f_{i,n,h}
         sigma_tot_{n,h}^2 = sum_i sigma^2_{i,h} * y_{i,n,h}

C1a + C1b enforce: mu_{n,h} + kappa * sigma_tot_{n,h} <= C_eff_n * z_{n,h}
which gives: P[ D_{n,h} <= C_eff_n * z_{n,h} ] >= 1 - eps

For eps=0.10, kappa=3.00: 90% probability of no overflow under worst-case
demand distribution consistent with the given mean and variance.

Practical implication:
  A single machine of capacity C_n can absorb demand from one tenant i without
  violating C1a only if:
    f_{i,n,h} + kappa * sigma_frac * u_{i,h} <= C_n
  => u_{i,h} * (1/1 + kappa*sigma_frac) <= C_n
  => u_{i,h} <= C_n / (1 + kappa*sigma_frac) = one_node_max

  For C_n=40 GB, kappa=3, sigma_frac=0.20:
    one_node_max = 40 / (1 + 3*0.20) = 40 / 1.6 = 25 GB

  Setting usage_min > 25 GB forces the model to assign >= 2 machines per tenant,
  which is the key design choice that ensures m_min >= 2 naturally.

  Note: sigma^2 is based on the PRE-FEEDBACK demand u_{i,h}, not u_fb_{i,h}.
  This means the Cantelli buffer is sized by the base uncertainty level, while
  C3 requires satisfying the inflated (feedback-adjusted) demand.


================================================================================
§6  OBJECTIVE
================================================================================

  Minimize:
    lam_0 * INFRA_COST
    - lam_1 * sigma
    - lam_2 * MIX_TOTAL

  where:
    INFRA_COST  = sum_{n in M_b} pi_n * z_on_n
                  (cost of activating additional machines)
    sigma       = minimum demand-satisfaction ratio across shared tenants
    MIX_TOTAL   = sum_{n in M, h in H} mix_{n,h}
                  (total machine-period pairs with both heavy + light tenants)

  In simulation:
    lam_0 = 0.0 (infra cost zeroed — always-on machines are pre-paid;
                  model distributes freely rather than packing into minimum)
    lam_1 > 0   (fairness rewarded)
    lam_2 > 0   (mixing rewarded)


================================================================================
§7  FEEDBACK INTEGRATION
================================================================================

After each planning horizon, the realtime layer reports:
  - v_bar_n: rolling SLA violation rate per machine (rolling k_window average)
  - W_bar_i: average scheduling wait time per tenant (in intervals)

These update plan parameters for the NEXT horizon:
  C_eff_n  = C_n * (1 - alpha * v_bar_n)
  u_fb_ih  = u_ih * (1 + beta * min(2, W_bar_i / W_bar_ref))

Effect:
  - High violation rate (v_bar_n -> 1): C_eff_n shrinks toward 0.5 * C_n.
    Fewer tenants can be packed onto the stressed machine.
  - High wait time (W_bar_i >= W_bar_ref): demand inflated by (1+beta) = 1.30.
    At W_bar_i = 2*W_bar_ref: max inflation = (1+2*beta) = 1.60.
  - The min(2,...) cap prevents infeasibility: with C_n=40 GB and kappa=3,
    a 1.60x scale still allows feasible assignment with enough machines.

Default calibration:
  alpha = 0.5, beta = 0.3, W_bar_ref = 10 intervals
  At W_bar_i = 10 (one reference period of waiting): scale = 1.30x
  At W_bar_i = 20 (two reference periods): scale = 1.60x (capped)

First run (no history):
  v_bar_n = 0.0 for all n -> C_eff_n = C_n (no capacity shrinkage)
  W_bar_i = 0.0 for all i -> u_fb_ih = u_ih (no demand inflation)


================================================================================
§8  OUTPUT FORMAT AND REALTIME INTEGRATION
================================================================================

Plan output structure:
  {
    "intervals": [
      {
        "interval": 0,   # period index h in H
        "groups": [
          {
            "tenant_ids":  [i_excl],            # exclusive group
            "machine_ids": [n1, n2],
            "exclusive":   True
          },
          {
            "tenant_ids":  [i1, i2, i3],        # shared group (all shared tenants)
            "machine_ids": [n3, n4, n5, n6],
            "exclusive":   False
          }
        ]
      },
      { "interval": 1, "groups": [...] },
      ...
    ]
  }

How the Cluster Manager uses this:
  Each scheduling interval:
  1. Resolve period h = (sim_interval // period_steps) % |H|
  2. Get group list for period h
  3. For each group in order:
     a. Sort queue to jobs in group's tenant_ids (FIFO: oldest first by arrival_round)
     b. Filter nodes to group's machine_ids
     c. Call realtime solver: placements = solve(group_jobs, group_nodes, W_t, K)
     d. Place assigned jobs; unplaced jobs get wait bump and stay in queue
  4. Remove placed jobs from queue; update W_t

FIFO ordering:
  group_jobs = sorted(queue_jobs_in_group, key=lambda j: j.arrival_round)
  Oldest jobs are presented first to the solver. Their accumulated W_t weight
  boosts their priority weight in the solver objective, ensuring long-waiting
  jobs are served before newer arrivals.

Exclusive vs shared:
  - Exclusive groups: one group per exclusive tenant, dedicated machines.
  - Shared group: all shared tenants in one group, can use any of their assigned
    machines. Tenants within the group compete for the machines via the realtime
    MILP, with W_t weighting providing fair scheduling.


================================================================================
§9  SOLVER CONFIGURATION
================================================================================

Model class: Mixed-Integer Second-Order Cone Program (MISOCP)
Solver: Gurobi (requires valid WLS academic or commercial license)

Default parameters:
  use_socp = True     (MISOCP mode; ALWAYS default everywhere)
  TimeLimit = 30 s    (simulation); 120 s (tests)
  MIPGap    = 0.05    (5% optimality gap, sufficient for planning)

Variable counts (approximate):
  Binary:     |T_s|*|M|*|H|  (y vars)
            + |M_b|          (z_on vars)
            + |T_e|*|M|      (e vars)
            + |M|*|H|        (z vars)
            + 3*|M|*|H|      (mix: hH, hL, mix vars)
  Continuous: |T_s|*|M|*|H|  (f vars)
            + |M|*|H|        (t vars, SOCP only)
            + 1              (sigma)

Typical scale:
  Small (4 tenants, 8 nodes, 3 periods): ~500 binary vars, ~200 continuous
  Medium (8 tenants, 15 nodes, 4 periods): ~3000 binary vars, ~700 continuous
  Large (15 tenants, 25 nodes, 8 periods): ~12000 binary vars, ~3000 continuous

Feasibility conditions:
  - Enough machines so that m_min machines per tenant can be assigned without
    violating C_sep (exclusive machines not shared).
  - u_{i,h} + kappa*sigma_frac*u_{i,h} <= sum_n C_eff_n (across enough machines)
    i.e., u_{i,h} * (1 + kappa*sigma_frac) <= m_min * C_n approximately.
  - Feedback inflation must not push u_fb above the feasible demand ceiling.
    The min(2,...) cap ensures max scale = 1 + beta*2 = 1.60.

Sensitivity summary (from plan_ahead_sensitivity.py):
  - epsilon in [0.05, 0.30]: feasible. Below 0.05 (kappa > 4.36): infeasible
    due to oversized Cantelli buffer.
  - Exclusive count: objective drops sharply when T_e > |T|/2 (shared pool too small)
  - Node capacity: needs C_n >= u_ih / (1+kappa*sigma_frac) for at least m_min nodes
  - lam1 (fairness): sigma jumps to 1.0 for lam1 > 0 on balanced instances
  - lam2 (mix bonus): objective grows linearly, promoting co-location aggressively


================================================================================
§10  CONNECTION TO CAPSTONE PAPER / PRIOR FORMULATION
================================================================================

The original (Chaudhari 2025-inspired) formulation used:
  - Per-workload covariance matrix Sigma_r (requires workload-level data)
  - Admission variables a_i (tenants could be rejected)
  - Revenue terms pi_bar_i, v_op_i (billing model)
  - Priority hints (y was a soft signal, not a hard assignment)

The current formulation changes:
  1. Tenant-level vs workload-level: u_{i,h} is aggregate tenant demand,
     not per-workload. This is more practical (forecastable from history).
  2. No admission rejection: all tenants are always served (C_share enforced).
     This matches multi-tenant SLA requirements where rejecting is not allowed.
  3. Exclusive/shared split: formal T_e / T_s partition handles mixed workloads
     (isolation-required tenants vs shared-pool tenants).
  4. Hard assignments: y_{i,n,h}=1 means the Cluster Manager actually sends
     tenant i's jobs to machine n. Not a priority hint — a hard routing decision.
  5. MISOCP default: SOCP mode is always on. MILP mode was needed only for
     debugging; the cone is what makes the formulation academically rigorous.
  6. Feedback loop: v_bar_n, W_bar_i fed from realtime into plan-ahead parameters,
     creating a closed control loop (adaptive scheduling).
